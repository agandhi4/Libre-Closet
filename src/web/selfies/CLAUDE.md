# Outfit selfies

`src/web/selfies/` (#19; plan section 13): a mirror photo as the record of what was worn. **The owner's own, like the calendar**: every query is scoped to the owner, another user's entry, selfie or photo name is a 404, and nothing reaches a grantee, the share page, Open Graph or another user's MCP tools.

- **Table `selfie`** (`drizzle/0020_outfit_selfies.sql`): `owner_id`, `day`, `outfit_calendar_id` (nullable, unique, `ON DELETE SET NULL`), `photo_id` (unique, `ON DELETE CASCADE` from `file`), `created_at`. **A row, not the plan's `outfit_calendar.photo_id`**, because a selfie outlives its entry when the outfit is deleted: the outfit's deletion detaches wears (the #7 rule) and the selfie is the record of the same day, so the entry reference goes null and `day` and `owner_id` keep the look on the calendar. One home for every selfie means one reference for reconciliation, one writer and one way to draw it.
- **One writer** (`queries.ts`): `setEntrySelfie` (a Queryable; the bytes already stored) marks the entry worn through `setEntryWorn` (locking it, so two uploads take turns), inserts the photo row as `unwanted` (no cutout, never queued) and inserts the selfie or repoints it, deleting the replaced photo's row; `deleteSelfie`; `deleteEntrySelfie` (inside `deleteEntry`, before the entry, since the foreign key would keep it). `writes.ts` holds the commit contract: `attachSelfie` (looks the entry up before reading the body: not the owner's 404, a later day 409; bytes deleted on a refusal or rollback; the replaced photo unlinked after commit) and `removeSelfie`. Removing a selfie leaves the entry worn; unmarking an entry keeps its selfie.
- **Routes** (`routes.ts`): `POST /calendar/:id/selfie?returnTo=` (multipart `photo`, one file; `returnTo` is in the query because Photos drains every part but the photo; 303 through `safeReturnTo`, else the entry's week), `POST /selfies/:id/delete` (`returnTo` in the body), `GET /selfies/:fileName` and `/selfies/thumb/:fileName` (`?v=`, `selfieUrl`).
- **Served to their owner only** (decided in #19: a mirror photo is more personal than a garment's, and an unguessable name is a capability anyone it reaches holds for good): the image routes are session-checked (`isOwnSelfie`) and answer a bare 404 otherwise (not the error page, which echoes the path); `Cache-Control: private, max-age=31536000, immutable` keeps the immutable `?v=` model; the public `/file/**` routes refuse a selfie's name (`publicPhoto`, `src/web/files/references.ts`, one indexed lookup) and the share preview serves garment photos only (`findPhotoByShareableId` joins `garment`). **The service worker never stores a selfie** (no image route matches `/selfies/`, and one opened as a document is no page: `src/web/shell/session-caches.md`), so the browser's HTTP cache holds them: they show offline, and `Clear-Site-Data: "cache"` empties it. **Every way a session ends on a device sends that header** (`endSession`): sign-out, account deletion, and the first request after a session was ended elsewhere (a password changed on another device, `user:set-password`, the account deleted on another device, a secret rotation, expiry), which the session resolver answers with the cookie cleared and the header (Request security, Session revocation), so a revoked device never keeps the account's selfie bytes. Every fetch re-checks ownership regardless (another account's request 404s). A new way to end a session goes through `endSession`.
- **Taking one** (`views.tsx`): `EntrySelfie` on a calendar row, Today's planned card and the outfit page's Worn strip: without a selfie, a camera button (`<input type="file" accept="image/*" capture="environment">`, the rear camera for the mirror) and a library one (no `capture`), each a native multipart `PostForm` (`data-needs-network`); the input's `onchange` imports `photo-input` (the garment form's `preparePhoto`: 1600 px JPEG on the phone, HEIC left for the server) and submits. With one, `SelfieView`: the thumb, which opens a dialog with the whole photo (loaded only then), another from the camera or the library, and Remove.
- **Shown**: the calendar (`findEntries` reads each entry's through `entrySelfieSql`; `detachedLooksSql` a week's looks, both JSON subqueries of the week's one statement, #165), Today (the same `findEntries`), the outfit page's **Worn strip** (`outfitEntries`' `worn`: the outfit's entries worn or with a selfie, newest first, each with its selfie or the buttons, linking its week). `get_calendar` and `get_today` say `selfie: true|false`, never the image.
- **Deletion**: the entry (`removeEntry`: rows in one transaction, bytes after), the selfie (`removeSelfie`), the account (the file rows are the owner's, `deleteAccount` unlinks them), the outfit (kept, above); changing an entry's outfit (#69) keeps its selfie as a look too (`detachEntrySelfie`). Reconciliation counts `selfie.photo_id` as a reference (`photoIsReferenced`); `reconcile.spec.ts` proves an entry's selfie and a detached look survive beside a real orphan.
- **Logs** (context `Web`): `Selfie <id> of calendar entry <id> taken|replaced by user <id>: <file>; entry marked worn (<n> wears logged)|entry already worn`, `Selfie <id> removed by user <id>: <file>`, `Calendar entry <id> deleted by user <id> with its selfie <file>`; a refused public `/file` request for a selfie at warn (context `Web`).
- **Seed**: Theo's worn evenings and nights out of the last 28 days carry a selfie (`simulate.ts`, demo.md Simulation 6), drawn by `selfie-art.ts` (the outfit's garment art on a figure in a hall mirror, three rooms in turn) and written through `setEntrySelfie`.
- **The phone check** (manual, the camera itself): installed on an iPhone and an Android phone, tap the camera on Today's card: the rear camera opens (not the library), the photo comes back to Today marked worn; an iPhone's HEIC shows once taken. `test/selfies.spec.ts` covers the rest at 390 px (Playwright sets the camera's file).

## Gotchas

- **An `sr-only` input escapes a scroll container.** It is absolutely positioned, so without a positioned ancestor its containing block is the page: file inputs inside the outfit page's horizontal Worn strip widened the whole page to the strip's scroll width (1078 px at 390). The label that wraps one is `relative` (`SelfieUpload`).
