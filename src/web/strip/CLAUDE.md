# Snap strip

`src/web/strip/snap-strip.tsx` and `public/js/snap-strip.js` (#270, epic #268): the scroll-snap carousel whose centred item, with its neighbours peeking, is the choice. Extracted from Styling's rows; its other user is the plan review (#271, `src/web/plans/review-page.tsx`: tiles that are buttons or a `div` holding a link, and no hooks module).

- **The component**: `<SnapStrip name? value? size label listbox? focusable? class? attributes? >items</SnapStrip>` (`tapThrough`: on a `listbox={false}` strip a click on a tile's button or link is left alone instead of centring a neighbour, Ideas and Today; each size also names its `gap`, Ideas' is 4; `attributes`: an `id` or `data-*` on the strip; `<SnapStripsInit />` is the inline init a page without its own hooks module renders) renders a `relative` frame (`snap-strip-frame`) holding the strip (`role="listbox"`, `data-snap-strip`, the snap classes) and, when given a `name`, right after it the hidden `<input name value>` the choice is written into. **The contract:** that input is always the strip's `nextElementSibling` (the observer writes to it when the next sibling is a hidden input, else nothing: a strip without `name` still marks `data-selected`, as the shopping list's does), so any number of strips can share one container and each writes its own input. **`listbox={false}`** (with `snapItem({ listbox: false })`) is for a strip that is not a choice and whose tiles hold links: `role="group"`, no `option` role or `aria-selected`, which would make the links presentational to screen readers (the shopping list, #272). `snapItem({ value, selected, size, class? })` returns an item's attributes to spread on its element (`data-snap-item`, `data-snap-value`, `role="option"`, `data-selected` / `aria-selected`, snap-centred, `snap-always`, the size's width, `group/item` so children style off `data-selected`). The page owns the element, its look and any other state.
- **`size`** (`regular` w-28, `small` w-20 and `roomy` w-28, both larger from `lg` (Styling's rows), `card` w-56: a plan look, #291, and Goes-with's best outfits; `page`, `peek` and `pair` (Goes-with's, w-11/12), an idea card: `w-full` / `w-[85%]` on a phone, w-72 from `lg`, Ideas and Today, #321, and no spacers on a phone, so the first card sits flush left; `options`, a Muse need's option cards, #333: `w-[85%]` on a phone like `peek`, and from `lg` no strip at all, every item a `flex-1` column side by side, nothing scrolling and the step buttons hidden, through a size's own `strip` and `frame` classes) fixes the item width and the strip's end spacers together; see the comment on `SIZES` and Styling's #179 gotcha (spacers, not padding, for WebKit). Widths are whole class strings so Tailwind sees them.
- **The observer**: an IntersectionObserver per strip, rooted on it with `rootMargin: 0px -50% 0px -50%` (a zero-width line down the middle), writes the crossing item's `data-snap-value` into the strip's input and moves `data-selected` / `aria-selected`. It centres the `data-selected` item once when it first watches a strip. **With a mouse (#311)**: the frame also holds two `data-snap-step` buttons (previous/next, `aria-label`s `strip.PREVIOUS`/`NEXT`) after the input, shown only by the `fine` variant (`@media (hover: hover) and (pointer: fine)`, `main.css`): one markup, no UA sniffing. They and the ArrowLeft/ArrowRight keys (a document `keydown` when focus is in a strip, not in a field) centre the item beside the chosen one, so the choice moves through the observer and `snap-strip:choose` like a swipe. A keyboard step from an item's control moves focus to the same control of the new item once it is chosen (its controls are `invisible` until then). The buttons are `disabled` at either end, set in JS (`syncSteps`) as the selection changes; an inert target (a locked Styling row's neighbour) or an end is a no-op. Copy never names the gesture ("swipe"). `test/snap-strip-pointer.spec.ts`. **No touch or wheel handlers** (`test/styling.spec.ts` checks the app has none). A capture-phase document click centres a tapped neighbour (an item may be a boosted link whose htmx handler would otherwise navigate first); the chosen item's tap reaches the item.
- **Wiring**: `initSnapStrips(root)` from `'snap-strip'` (importmap, `layout.tsx`), called by the page's inline module on every visit (a boosted navigation brings new strips; a `<script src>` module runs once). `htmx:load` covers strips swapped in later, a strip's next page and history restores. Calling it twice is harmless.
- **Hooks for a page's own rules** (document listeners, nothing else): `snap-strip:choose` is cancelable, fires on the strip before an item is chosen (`detail.item`); cancelling leaves the choice as it is. `snap-strip:watch` fires on the strip after each (re)scan. Styling's locks use both (`public/js/styling.js`).
- **Not here**: locks, `inert`, paging, "No garment", what an item looks like. A new user supplies its item element and (if it has rules) a hooks module like styling.js.
