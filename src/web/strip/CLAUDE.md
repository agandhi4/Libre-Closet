# Snap strip

`src/web/strip/snap-strip.tsx` and `public/js/snap-strip.js` (#270, epic #268): the scroll-snap carousel whose centred item, with its neighbours peeking, is the choice. Extracted from Styling's rows, which stay its only user until the plan review (#271).

- **The component**: `<SnapStrip name value size label class? >items</SnapStrip>` renders the strip (`role="listbox"`, `data-snap-strip`, the snap classes) and, right after it, the hidden `<input name value>` the choice is written into. **The contract:** the input is always the strip's `nextElementSibling` (the observer reads it from there and throws if it is not an input), so any number of strips can share one container and each writes its own input. `snapItem({ value, selected, size, class? })` returns an item's attributes to spread on its element (`data-snap-item`, `data-snap-value`, `role="option"`, `data-selected` / `aria-selected`, snap-centred, `snap-always`, the size's width, `group/item` so children style off `data-selected`). The page owns the element, its look and any other state.
- **`size`** (`regular` w-28, `small` w-20) fixes the item width and the strip's end spacers together; see the comment on `SIZES` and Styling's #179 gotcha (spacers, not padding, for WebKit). Widths are whole class strings so Tailwind sees them.
- **The observer**: an IntersectionObserver per strip, rooted on it with `rootMargin: 0px -50% 0px -50%` (a zero-width line down the middle), writes the crossing item's `data-snap-value` into the strip's input and moves `data-selected` / `aria-selected`. It centres the `data-selected` item once when it first watches a strip. **No touch or wheel handlers** (`test/styling.spec.ts` checks the app has none). A capture-phase document click centres a tapped neighbour (an item may be a boosted link whose htmx handler would otherwise navigate first); the chosen item's tap reaches the item.
- **Wiring**: `initSnapStrips(root)` from `'snap-strip'` (importmap, `layout.tsx`), called by the page's inline module on every visit (a boosted navigation brings new strips; a `<script src>` module runs once). `htmx:load` covers strips swapped in later, a strip's next page and history restores. Calling it twice is harmless.
- **Hooks for a page's own rules** (document listeners, nothing else): `snap-strip:choose` is cancelable, fires on the strip before an item is chosen (`detail.item`); cancelling leaves the choice as it is. `snap-strip:watch` fires on the strip after each (re)scan. Styling's locks use both (`public/js/styling.js`).
- **Not here**: locks, `inert`, paging, "No garment", what an item looks like. A new user supplies its item element and (if it has rules) a hooks module like styling.js.
