# The duplicate check: "add a copy"

Part of the Wardrobe (`CLAUDE.md` in this directory); #20, plan section 18.

- **The rule is 18b's**, `nearDuplicates` (`src/wardrobe/goes-with.ts`): same category, same type, same colour set (never an empty one). The check asks it with `sameBrand`: a garment whose brand differs (both named, `brandKey`) is not a copy; a blank brand is unknown and still matches. "Goes with my closet" asks without it ("do I need another?" is about the kind). Never write a second rule: a new caller passes an option.
- **`lookalikes.ts`**: `closetLookalikesSql` (the candidates as a scalar subquery: the category's `inCloset` garments of the same type and the same colour set, which the rule needs anyway, so a check reads the few it may keep, not the whole category, #161; nothing is read without a category and a built-in colour) and `readClosetLookalikes` (the rule over them: the form's values read as a save reads them: category normalised, a type only of its category, built-in colours only; at most `LOOKALIKES_SHOWN` (3), newest first, minus the dismissed ids, or `exceptId` for a garment just saved); the form reads the candidates in its one statement (`form.md`), the region's refresh and the MCP through `closetLookalikes` (both in one). The SQL narrows, the rule judges: the brand is the rule's alone. `addCopies` (the one writer of "add a copy": `ownerTransaction`, one UPDATE that carries the checks on the row it locks; only a refusal reads the row again for its reason: `not-found`, `not-in-closet` or `too-many` past `QUANTITY_MAX`), `LookalikesQuery`. The "Not the same" list is comma-joined ids read by `readIdList` and written by `idListValue` (`urls.ts`, shared with the draft queue): malformed ids are dropped.
- **Where it shows**: the garment form when it adds to the closet (`addsToCloset`, `garment-form.tsx`: a new closet garment, whichever way it started, the link import's prefilled form included, and a clone of a closet garment; the clone mode carries `wishlist` for this). Not on an edit or a wishlist form. `renderGarmentForm` computes the first answer from the values it renders (a link import, a clone, a refused save arrive filled in); a refused `POST /wardrobe` or clone posts `lookalikesDismissed` back (`GarmentBody`, never stored) and the routes pass it on.
- **The region** (`lookalike-region.tsx`): `#garment-lookalikes` under Brand and Size, rendered once and never swapped; it listens for `change from:closest form` and asks `GET /wardrobe/lookalikes` (`lookalike-routes.tsx`, owner or MANAGE, always a fragment, a debug line when it matches) for its contents, sending only `category,type,color,brand,lookalikesDismissed` (`hx-params`). A clone's region addresses the requester's own wardrobe. "Not the same" is an `hx-get` whose `hx-vals` carries the list plus the ids shown; the hidden input in the answer keeps it for the next refresh.
- **"Add a copy"**: `POST /wardrobe/:id/copies` (owner or MANAGE: quantity is a garment property), one copy, 303 to the garment with `?copyAdded=1` (a toast); refusals are the error page (409, 404). The pending photo the form held is left, as Cancel leaves it (reconciliation). MCP: `add_garment_copy` calls `addCopies`; `add_garment_from_link` answers `lookalikes` for a closet save.

## Gotchas

- **The copy buttons belong to `LookalikeCopyForm`, never the garment form.** They sit above Save, and the first submit button of a form in tree order is its default button: inside the garment form, Enter in the name field would add a copy instead of saving. They join the empty form rendered after it through `form=` and name their route with `formaction`. `test/lookalikes.spec.ts` presses Enter with a match showing.
